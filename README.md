# xmip-core-transport

Direction-neutral Transport contracts for moving immutable Streams between Xmip and endpoints.

Receive and Send own orchestration, ports, groups, and locations. Transport owns byte movement and resource claims; it does not own authentication, message representation, contract evaluation, or operation semantics.

This crate is the common boundary: the `Transport` trait, `Arrived`, `Directions`, the error vocabulary (which takes the network primitives' failures with `From`, and becomes `xcore::Failure` with `From` — retryable as it was — so a technology whose attempt the resilience guards judge writes `?`), and resource claims. It holds what the SQL technologies share (`sql.rs`): where a send target puts its row, the one INSERT with its table and column quoted as the technology's `Dialect` says, the same statement taken apart for a far end, and the declared payload column; each technology passes its dialect, and nothing tells one from another by name; the target is read by `net::Target` against the schemes the dialect declares. It holds `Configured` (`configured.rs`), the companion every technology implements to declare its settings — each one's name, kind, default or requirement, meaning and side, in the shape `xmip-core` owns (`xcore::settings`, the one a contract's settings take too) — and to be built from a Location's address and settings read through that one declaration, so what `configure` refuses at start, what the language server and the desktop editor offer, and what the technology reads cannot disagree (ADR-0064, amendment 2026-09-26). It holds the loopback rig every technology's far end is built from (ADR-0051): the `Loopback` trait and its round — which goes in order on one thread where a technology declares `exchanges_in_order`, and releases a far end whose near end failed by poking a TCP listener, never a datagram far end (`FarEnd::datagram`) — the far ends `Listening` (TCP), `Bound` (UDP) and `Held` (in process), the `Standing` sessions of an in-process pair, `both_ends` and `poke`; a technology keeps only what its far end does with the exchange. The byte cursor and writer, hex, the CRCs and the varint are encoding primitives, and each technology takes them from `xmip-core-library-codec` itself, as it takes X.690 from `xmip-core-library-asn1` and the one refusal of a payload over a protocol's ceiling from `xmip-core-library-net` (`net::ceiling::within`). Its test support (`test-support`, from a technology's dev-dependencies only) carries the edge and sized payloads a loopback round is exercised with, and `latency`: a round's median, p99 and worst, and a plain loopback TCP wake measured beside it, so a technology holds its latency to a bound *apart from load* (the owner, 2026-09-26). Nothing in it names a protocol. Each transport technology is its own repository (ADR-0010) mounted directly under this one and depends on this crate, never the reverse; `architecture.toml` names them and carries each one's maturity, and this file does not repeat the list.

Its sockets (`socket.rs`, `sender.rs`) are opened once and waited on rather than polled wherever the operating system lets a safe call wait. `socket::accept_within` is the one bounded accept, for any `socket::Acceptor` — a TCP listener, a Unix domain socket's, a named pipe's: it waits on the listener's readiness, poll(2) or `WSAPoll` through `rustix`'s safe `event::poll`, and takes a connection as it lands, `accept_tcp` handing it back with Nagle's algorithm off as `net::connect` does; until 2026-09-27 the capability, the named pipe and the Unix domain socket each polled with a two-millisecond nap, and a Windows named pipe, which has no readiness a safe call can wait on, still naps a quarter of a millisecond between tries. `socket::connect_tcp` is `net::connect`, every address a name resolves to inside one deadline; it tried only the first until 2026-09-27. A send target and an origin are read by `net::Target`, in `xmip-core-library-net`, which every technology calls itself: `socket::target` split one on its first slash, the query left in the path, until 2026-09-28. `sender::Sender` is the datagram socket a UDP technology sends from, bound once per address family — IPv6 targets included — and kept by the transport and its clones, with `exchange` holding it for a request and its answer after reading off whatever came late; nine technologies bound a new IPv4 socket for every datagram until 2026-09-27.

A Receive Location's listener is bound once and kept (`kept.rs`): `kept::Kept` holds whatever the technology binds — a TCP listener, a datagram socket, a Unix domain socket's listener, a named pipe — bound by the technology's own `bind` on the first receive and taken from by every receive after, so what connects or arrives between two receives waits in the operating system's backlog or buffer and the next receive takes it. Thirty technologies bound a new listener in every `receive`, took one exchange and dropped it until 2026-09-27, so a peer that connected between receives was refused and a datagram sent then was lost. `serving::Serving` is a kept listener and the connections its peers keep open on it (at most `MOST_KEPT`): one readiness wait over all of them hands each receive the next exchange from whichever peer speaks first, a new one accepted and kept or a kept one's next — what one exchange on a connection is stays the technology's (the http technology's `inbound`). `kept::held_across_receives` (test support) holds a technology to it: payloads sent to the kept address while it receives, every one taken in order by receives that bind nothing.

A Send Location's sessions are opened and logged in once and kept (`pool.rs`): `pool::Pool` holds, per address, the sessions a transport and its clones send on — an HTTP connection, an MQTT or NATS client, an AMQP channel in confirm mode, a SQL login, an SMB tree, an SSH connection — each taken for one exchange and put back after, so sends on several threads each have one. A session says through `pool::Pooled::usable` whether it can carry another exchange, and `pool::alive` is the check one over TCP makes: a peek that sees a far end that hung up without waiting on it. Before a pool opens a session it lets go every kept one that is no longer usable, under every address, so a session whose far end hung up is closed by the next one opened rather than kept under an address never asked for again — until 2026-09-29 the Playground's nodes kept one such socket a round, in `CLOSE_WAIT`, until the machine ran out of ephemeral ports; `pool::quiet` is the stricter check for a session whose far end speaks only when asked. One that fails on reuse is dropped and the exchange goes again on a new one, so a send is carried at least once, and a send that is not idempotent can be carried twice where the first attempt reached the far end and only its answer was lost. The http technology's `endpoint::Connections` is this pool's instance for HTTP; twenty technologies connected, logged in and closed for every message until 2026-09-27. A Receive Location that connects out — a broker consumer, a SQL poll, a mailbox, a file share, a plant read — keeps its session in the same pool from 2026-09-28: logged in on its first receive, reused by every receive after, replaced when the far end closed it; a subscription or consumer stays attached between receives, and `pool::delivered` drains one until it is quiet, telling a quiet subscription (kept) from a broken one (replaced). POP3 alone connects per receive, because its session fixes the maildrop at login and commits deletes at QUIT. `login::Login` is the user and password a technology logs in with, printed without its password; eight technologies and MQTT declared the pair each until the same day. Where a protocol frames a Stream by the connection itself — raw TCP and a Unix domain socket, closed to end it; COTP class 0, whose receiver takes a caller's messages until it disconnects and which acknowledges none; a WebSocket, whose receiver takes one frame a connection with nothing said back — the send connects per message, because a kept connection could not tell a Stream that landed from one written into a closing socket.
