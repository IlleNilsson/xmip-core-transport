# xmip-core-transport

Direction-neutral Transport contracts for moving immutable Streams between Xmip and endpoints.

Receive and Send own orchestration, ports, groups, and locations. Transport owns byte movement and resource claims; it does not own authentication, message representation, contract evaluation, or operation semantics.

This crate is the common boundary: the `Transport` trait, `Arrived`, `Directions`, the error vocabulary (which takes the network primitives' failures with `From`), resource claims, the ceiling a connection is read for, and what several technologies frame with: the DNS name form. It holds the loopback rig every technology's far end is built from (ADR-0051): the `Loopback` trait and its round — which goes in order on one thread where a technology declares `exchanges_in_order`, and releases a far end whose near end failed by poking a TCP listener, never a datagram far end (`FarEnd::datagram`) — the far ends `Listening` (TCP), `Bound` (UDP) and `Held` (in process), the `Standing` sessions of an in-process pair, `both_ends` and `poke`, and `ceiling::within`, the one refusal of a payload over a protocol's ceiling; a technology keeps only what its far end does with the exchange. The byte cursor and writer, hex, the CRCs and the varint are encoding primitives, and each technology takes them from `xmip-core-library-codec` itself, as it takes X.690 from `xmip-core-library-asn1`. Nothing in it names a protocol. Each transport technology is its own repository (ADR-0010) mounted directly under this one and depends on this crate, never the reverse; `architecture.toml` names them and carries each one's maturity, and this file does not repeat the list.
