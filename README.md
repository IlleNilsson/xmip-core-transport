# xmip-core-transport

Direction-neutral Transport contracts for moving immutable Streams between Xmip and endpoints.

Receive and Send own orchestration, ports, groups, and locations. Transport owns byte movement and resource claims; it does not own authentication, message representation, contract evaluation, or operation semantics.

This crate is the common boundary: the `Transport` trait, `Arrived`, `Directions`, the error vocabulary (which takes the network primitives' failures with `From`, and becomes `resilience::Failure` with `From` — retryable as it was — so a technology whose attempt the resilience guards judge writes `?`), resource claims, and what several technologies frame with: the DNS name form. It holds what the SQL technologies share (`sql.rs`): where a send target puts its row, the one INSERT with its table and column quoted as the technology's `Dialect` says, the same statement taken apart for a far end, and the declared payload column; each technology passes its dialect, and nothing tells one from another by name. It holds `Configured` (`configured.rs`), the companion every technology implements to declare its settings — each one's name, kind, default or requirement, meaning and side, in the shape `xmip-core` owns (`xcore::settings`, the one a contract's settings take too) — and to be built from a Location's address and settings read through that one declaration, so what `configure` refuses at start, what the language server and the desktop editor offer, and what the technology reads cannot disagree (ADR-0064, amendment 2026-09-26). It holds the loopback rig every technology's far end is built from (ADR-0051): the `Loopback` trait and its round — which goes in order on one thread where a technology declares `exchanges_in_order`, and releases a far end whose near end failed by poking a TCP listener, never a datagram far end (`FarEnd::datagram`) — the far ends `Listening` (TCP), `Bound` (UDP) and `Held` (in process), the `Standing` sessions of an in-process pair, `both_ends` and `poke`, and `ceiling::within`, the one refusal of a payload over a protocol's ceiling; a technology keeps only what its far end does with the exchange. The byte cursor and writer, hex, the CRCs and the varint are encoding primitives, and each technology takes them from `xmip-core-library-codec` itself, as it takes X.690 from `xmip-core-library-asn1`. Its test support (`test-support`, from a technology's dev-dependencies only) carries the edge and sized payloads a loopback round is exercised with, and `latency`: a round's median, p99 and worst, and a plain loopback TCP wake measured beside it, so a technology holds its latency to a bound *apart from load* (the owner, 2026-09-26). Nothing in it names a protocol. Each transport technology is its own repository (ADR-0010) mounted directly under this one and depends on this crate, never the reverse; `architecture.toml` names them and carries each one's maturity, and this file does not repeat the list.

Its sockets (`socket.rs`, `sender.rs`) are opened once and waited on rather than polled wherever the operating system lets a safe call wait. `socket::accept_within` is the one bounded accept, for any `socket::Acceptor` — a TCP listener, a Unix domain socket's, a named pipe's: it waits on the listener's readiness, poll(2) or `WSAPoll` through `rustix`'s safe `event::poll`, and takes a connection as it lands, `accept_tcp` handing it back with Nagle's algorithm off as `net::connect` does; until 2026-09-27 the capability, the named pipe and the Unix domain socket each polled with a two-millisecond nap, and a Windows named pipe, which has no readiness a safe call can wait on, still naps a quarter of a millisecond between tries. `socket::connect_tcp` is `net::connect`, every address a name resolves to inside one deadline; it tried only the first until 2026-09-27. `sender::Sender` is the datagram socket a UDP technology sends from, bound once per address family — IPv6 targets included — and kept by the transport and its clones, with `exchange` holding it for a request and its answer after reading off whatever came late; nine technologies bound a new IPv4 socket for every datagram until 2026-09-27.
